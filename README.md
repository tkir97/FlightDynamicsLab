# Flight Dynamics Lab — JSBSim C172 and F-15

A browser flight simulator with a 3D cockpit, satellite terrain, instruments and live forces. JSBSim 1.2.4 runs as WebAssembly inside a dedicated module worker. Aircraft data and runtime assets are served locally with the Site; there is no remote flight dynamics service.

## Run and verify

Serve `dist/` over HTTP, for example `python -m http.server 8000 --directory dist`. Modules and workers cannot run from a local `file:` page. Run `npm test` with Node 20+; no dependency installation or compilation is required. Tests execute the actual shipped WASM engine, not a mocked replacement.

## Aircraft model

`dist/vendor/jsbsim/data/aircraft/c172s-lab/c172s-lab.xml` derives from the upstream C172R model at JSBSim revision `1a2e114d79af2430db02a4f7a4a85328cdc5d403`. That file already uses a 180 hp IO360C engine and the Clark Y7570 propeller. We add 114 lb at its empty CG, bringing initial gross weight to 2,550 lb. Fuel burns and mass/CG evolve through JSBSim. Aerodynamics, inertia and propulsion otherwise remain upstream estimates. This is a C172S approximation, not a validated C172S flight-test database. The legacy model's handbook-fit results do not apply to this engine.

Mixture is automatically leaned using atmospheric pressure / 2116.22 psf. Flaps remain up. Native JSBSim gear contact, suspension, tire friction, wheel braking and nose steering now support landing and taxiing. The terrain remains a flat 25.6032 m MSL plane.

## Runtime and controls

- `dist/jsbsim-flight.mjs` loads the runtime/data, performs a full six-axis trim, converts existing control angles to JSBSim normalized commands, and converts properties to SI units.
- `dist/worker.mjs` owns the engine and advances it at a fixed 1/240 s step. Rendering never advances physics. Catch-up is bounded; overloaded browsers slow simulation time. Pause clears pending elapsed time. Startup/reset failures disable flight until a successful retry.
- `dist/app.mjs` supplies controls, instruments, pause/reset, crosswind and 22-column CSV export. Arrow keys pitch/roll, A/D rudder, W/S throttle, Space pause, R reset and C cockpit/chase. Release controls to return to the full-trim positions, including lateral trim for propeller effects. The trim slider offsets elevator angle from the initialized trim; it is not an independent cockpit trim-wheel mechanism.
- `dist/render.mjs` and `dist/cockpit.mjs` render the view, live gauges and animated yoke. Drag to look, scroll to zoom and double click to centre. The panel is a simplified analog cockpit, not a replica of the 172S Nav III G1000.
- `dist/imagery.mjs` streams attributed Esri World Imagery into a north-up map. `dist/terrain.mjs` uses perspective-correct inverse ground mapping. Imagery does not provide elevation or collision geometry. Four concurrent image requests and a 192-tile cache bound network work.

The adapter exposes local NED metres and a scalar-first quaternion rotating forward/right/down body vectors into NED. JSBSim geodetic latitude/longitude map to the existing local Mercator plane. This is a local-area rendering approximation; JSBSim retains its own Earth dynamics. CAS, TAS, aerodynamic lift/drag, propeller thrust, shaft power, density, pressure and load factor come from JSBSim. The drag split is the model's alpha-dependent `CDwbh` contribution versus all other contributions; it is **not** a separately resolved profile/induced drag split. CSV headers reflect that distinction.

JSBSim is LGPL-2.1 and the SDK is MIT. The modified aircraft XML includes its change description and retains upstream notes.

## Validation

The JSBSim checks cover all nine offered initial speed/altitude combinations for 60 seconds of trimmed flight, SI/attitude/geographic conversion, pitch/roll/rudder directions, throttle/thrust response, crosswind, fuel burn, and reset. Worker checks cover real bootstrap, pause/resume, CSV and error recovery. These establish integration correctness and stable initialization; they do not establish aircraft handling fidelity.

The previous custom engine remains in `dist/physics.mjs` and `dist/aircraft.mjs` for historical numerical tests and shared vector helpers; it no longer advances the flight or supplies live forces. `MODEL.md` preserves its historical calibration.

## F-15 Eagle

Select F-15 in Flight Configuration to reset into trimmed jet cruise. Presets are 150/180/220 m/s at 1,500/3,000/6,000 m MSL. The upstream F-15 model uses two F100-PW-229 engines; total thrust sums both engines. Throttle up to 100% is dry/military power; 100–200% requests increasing afterburner. N1 replaces piston shaft-power telemetry, Mach is displayed, and speed gauges expand to 800 KCAS. Returning to the C172 restores its presets and controls.

The shipped F-15 XML corrects two unbound aileron-scale inputs to consume the existing kinematic output. Aerodynamics remain estimated upstream data. Gear is up and speedbrake is stowed; native ground handling is enabled. The cockpit is the shared simplified instrument panel, and chase view uses a simplified swept-wing, twin-fin Eagle silhouette. No combat systems or authentic F-15 avionics are simulated.

F-15 tests cover all nine presets for a simulated minute (less than 25 m altitude drift and 1 m/s speed change), control response, both engines, afterburner thrust, fuel burn and switching back to the C172. Slow trimmed-flight drift is expected as substantial jet fuel consumption changes loading. These are integration checks, not validation against F-15 flight-test data.

## Uploaded Boeing 737-800 cockpit

The third aircraft option pairs the user's uploaded 737-800 interior with the generic JSBSim `737` aircraft and two CFM56 engines. These dynamics are not a validated 737-800 model. Cruise presets are 180/200/220 m/s at 3,000/6,000/9,000 m. Gear/flaps remain up and the speedbrake stowed. Throttle is capped at 100%, without afterburner. The XML's external input sockets were removed; all flight controls remain in the worker through the property API.

The supplied GLB includes approximately 1.75 million triangles, 100 materials, no textures and no animations. Its metadata credits hakai315 and CC BY 4.0. `dist/assets/737-cockpit-NOTICE.html` retains credit, source, license and modifications. The upload was preserved; an optimized 8.37 MB rigged copy replaces an 86.08 MB original (decimal sizes). Equivalent vertices/materials were deduplicated, scene transforms flattened, meshes joined, and quantized geometry Meshopt-compressed; no simplification was used.

`dist/model-cockpit.mjs` lazily loads Three.js and the GLB when the 737 cockpit is selected. It composites a transparent WebGL interior over the existing satellite/world renderer. Camera placement is in the supplied model's captain-seat coordinates; +Z is forward, -X is right, and +Y is up. The head-look basis and asymmetric projection match the existing view, with an initial 0.16 rad downward look to frame the panel. Raster width is capped at 1,200 pixels. GPU context/load failures show an explicit status and retain the simplified cockpit. The imported switches remain decorative; five main display surfaces now show live JSBSim instruments. Chase mode uses a simplified reference airliner exterior, because no exterior geometry was supplied.

The bundled Three.js 0.186.1 runtime includes GLTFLoader and MeshoptDecoder, with licenses in `dist/vendor/three`. The bundling entry is `scripts/cockpit-runtime-entry.mjs`. To regenerate it, install `three@0.186.1` and `esbuild`, then bundle that entry with `--bundle --minify --format=esm --platform=browser --outfile=dist/vendor/three/cockpit-runtime.mjs`. To regenerate the rigged optimized asset, use `scripts/rig-737-yokes.mjs` as described below; generic scene flattening would remove the yoke pivots.

Checks execute all nine generic 737 presets, throttle limits and aircraft switching, parse the actual compressed GLB with the shipped loader, and verify the cockpit head-look basis. Geometry/camera views were inspected with a software render. Full browser GPU QA was unavailable in this environment.

The 737 main panel now carries five live Canvas-textured screens: captain and first-officer PFD/ND pairs and a central engine display. They update at 20 Hz from JSBSim telemetry and remain depth-tested against the cockpit geometry. IAS, altitude, vertical speed, attitude, true heading, Mach, airport bearing, N1/N2, fuel flow and fuel quantity are live. Navigation uses a fixed 20 NM range and Dhahran start reference; no FMS, autopilot, instrument failure or clickable-switch simulation is provided. Display artwork and placement were checked with software rendering; browser WebGL QA was unavailable.

Turbulence control uses JSBSim 1.2.4's native Dryden MIL-STD-1797A formulation (`atmosphere/turb-type=3`). Off sets severity 0; Light/Moderate/Severe use the bundled FGWinds reference presets (severity 3/4/6 and 20 ft AGL wind parameters 25/50/75 ft/s). These are model intensity presets, not measured weather or aircraft-specific encounter classifications. The model varies gust velocities and angular rates with airspeed, altitude above terrain, and wingspan. It runs on simulation time, pauses with flight, and is applied after calm-air trim on reset. Steady crosswind remains separate.

F-15 keyboard/touch controls now use a full-travel virtual stick, reaching full modeled deflection in 0.18 s from center and recentering in 0.12 s. Travel respects each asymmetric surface limit and trim; JSBSim retains its native actuator dynamics. Other aircraft retain their prior input scaling. This removes the prior partial-authority keyboard mapping. An approximate augmentation layer now interprets stick inputs as commands when Augmented mode is selected.

Terrain no longer has a 30 km rendering cutoff. Camera rays intersect an Earth-radius sphere centered below the camera's local tangent plane; altitude-dependent zoom-7 backdrop tiles cover the geometric horizon in all directions, with zoom-9/11/14 layers supplying progressively finer imagery. This remains satellite imagery on a smooth surface, not elevation terrain. Distant scenery fades into matching atmospheric haze. The sky is a bounded direction-based raster with an altitude-dependent blue gradient, fixed daytime sun glow, and procedural high-cloud patterns drifting on simulation time. Clouds are visual only; they are not live weather or volumetric cloud flight.

F-15 Augmented mode (default) runs a Flight Lab control law at 240 Hz ahead of the native actuators: roll-rate proportional/integral control with neutral-stick damping, pitch load-factor/pitch-rate feedback with bounded integration, pressure-dependent gain scheduling, speed-dependent pitch-rate targets, and a washout yaw damper plus sideslip feedback. The bank is not automatically leveled on stick release. Soft feedback unloads excessive G and AoA; this is not guaranteed hard envelope protection. The existing model's aerodynamics and actuator limits still determine attainable rates and loads. Direct mode bypasses augmentation for comparison; mode selection persists across resets. These are original approximate control laws, not published F-15 CAS/SAS data, and are not validated against the real aircraft. Tests cover nine cruise presets, roll release, pitch response, scheduling, feedback signs and worker lifecycle.

F-15 roll responsiveness tuning: the effective lateral control moment (`ClDa`) is multiplied by 3.2, retaining the upstream AoA table and actuator travel limits. Augmented full stick commands 3 rad/s (172 deg/s) before AoA attenuation; feedforward, rate feedback and bounded integral gain are retuned for the added authority. Across the nine offered cruise presets, a full-stick step reaches approximately 110–140 deg/s after 1 s; after a further 1 s at neutral stick, residual roll rate is below 3 deg/s. This is approximate combined lateral-authority tuning, not validated F-15 aerodynamic data or a separately modeled differential-stabilator system.

`npm run validate:f15` generates 81 calm-air roll-step, roll-doublet and pitch-doublet runs at the nine cruise starts, comparing current augmented, current direct, and earlier aerodynamic authority with direct input. It writes `dist/validation/f15-report.json`, `f15-traces.csv` and `source-audit.json`; the interactive report is `dist/validation/f15.html`. The proposed validation target is clean F-15C/PW-220, while the current model remains generic/PW-229. No matched flight reference is available, so no real-aircraft RMSE, accuracy, or validation claim is produced. NASA sources are explicitly qualified or excluded in `validation/sources.json`. No aircraft tuning is performed by the reporting script.

## Public-evidence control update

NASA TM-72861 (https://ntrs.nasa.gov/citations/19790015808), appendix pp. 12–13, supports separate pilot and augmentation paths, washed-out pitch-rate feedback, ±10° pitch CAS authority, limiter breakpoints +5°/−19°, and ±5° yaw CAS authority. Pitch and yaw corrections now respect these limits in degrees, including asymmetric stabilator travel and available headroom. Pitch integral feedback stops accumulating into a saturated correction. Pilot rudder gearing is independent of the CAS pressure gain. The model’s existing small native yaw damper remains active.

This is an evidence-informed approximation, not an authentic CAS reproduction. The linear limiter taper, 2 s washouts, feedback gains, keyboard gearing and roll authority remain estimates. Mechanical PRAD/RRAD schedules and differential stabilators are not separately resolved. Soft G/AoA protection shares limited authority and cannot guarantee envelope limits. The report compares seven nominal dimensions/travel limits with NASA Table 1 and regenerates all 81 response cases. It does not treat those checks as measured-flight validation. The NASA test aircraft/control configurations differ from the proposed F-15C/PW-220 target.

## 737 yoke animation

Both uploaded yokes now have separate column and wheel pivots. Pitch input pivots the column forward/back by up to 10°; roll rotates the wheel by up to 70°, clockwise for a right-roll command from the pilot seat. Travel is a visual approximation. A 70 ms visual filter smooths movement; pilot-input metadata is carried through the worker independently of surface commands. Releasing controls returns both yokes to neutral; reset clears animation history. Trim and turbulence do not drive the yoke. No flight-dynamics coefficients changed.

`scripts/rig-737-yokes.mjs original.glb output.glb` reconstructs the pivots from the original upload using glTF Transform 4.5.1 and meshoptimizer. It preserves geometry, joins meshes within each rig group and uses Meshopt compression without simplification. It requires the original uploaded GLB and those development dependencies; the shipped browser asset needs no build step.

## Flaps, landing gear and ground handling

Use Landing & Ground in the sidebar, or G (gear), [ / ] (flap detents), hold B (wheel brakes), P (parking brake), and A/D (nose steering). The C172 has fixed gear and 0/10/20/30° flaps. The generic 737 has eight native flap actuator steps, shown with familiar detent labels; these are not calibrated 737-800 flap angles. F-15 flaps are unavailable because its bundled XML has no flap actuator/aerodynamics. Gear and flap motion use native actuator times and change modeled aerodynamic forces. The chase silhouettes show approximate gear geometry. Cockpit flap/gear levers remain decorative; the sidebar and shortcuts operate the systems.

Start position offers cruise, parked ground initialization (native ground trim, idle, gear down, parking brake on), or a level low approach at 50 m AGL, gear down and flaps up. Low-approach speeds are C172 35 m/s, F-15 100 m/s and generic 737 110 m/s, chosen for stable trim in these models, not handbook landing speeds. Release parking brake, add power and use A/D to taxi. Gear retraction is inhibited while supported on the wheels. Steering authority tapers with ground speed. F-15 flight augmentation is bypassed on the wheels.

Contact uses the existing flat 25.6032 m MSL plane with uniform model friction everywhere. Satellite runway pixels do not define pavement, terrain elevation or obstacles; starts are at the existing airport origin, heading north, not aligned final approaches. Normal wheel contact no longer freezes the flight. A stop remains if the aircraft origin penetrates the ground; structural damage, tire failures, runway-specific friction and validated landing loads are not modeled. Tests cover parked support, taxi/braking, gear interlock/actuator motion, flap force changes and continued motion after gear-down touchdowns for all aircraft.

Default start: latitude 26.246748500933275, longitude 50.15228660429263, true heading 000°. Ground elevation uses OEDR’s published aerodrome elevation of 84 ft (25.6032 m) as a flat-plane approximation, not a surveyed elevation at this exact coordinate.

## F-15 game missiles
Select F-15, resume airborne flight and press X or Fire missile. Eight fictional rounds alternate launch sides; reset reloads. Projectiles inherit aircraft velocity and orientation, accelerate briefly, coast under simplified drag/gravity, show trails and disappear on flat-ground impact or after 12 seconds. Pause freezes projectiles and cooldown. Launches are inhibited on ground and in other aircraft. No real missile performance, aircraft mass/drag changes or operational weapon systems are modeled.

## AI aircraft scenarios
F-15 resets start one nearby opposing patrol. Add opponent/friendly buttons spawn up to four aircraft; Clear removes them. T or Next target selects an opponent; a fictional forward-view lock enables simplified pursuit homing on subsequent X launches. Hits remove an opponent and increment the counter. Friendly units are excluded from targeting and hit detection. Motion uses kinematic patrol circles, approach-player mode, return toward patrol area and a simple evasive turn when a game missile is nearby. AI cannot fire, collide with the player or model real combat tactics. AI markers appear in both 3D views and satellite maps. Pause freezes all motion; flight reset restores the default scenario and missile inventory.

## Eagle-style radar display
The F-15 has a green range/azimuth B-scope on its simplified cockpit panel and a V-toggle readable radar view. Range scales 5/10/20/40 NM, Search sweep and single-target Track view, altitude in thousands of feet, closure in knots, selectable contacts and friendly scenario symbols are implemented. Tracks refresh on the game scan, coast/fade, disappear after six seconds or unit removal; Track continuously refreshes its selected contact inside the game scan volume. Radar power inhibits radar-assisted missile lock; existing fictional missile launch envelope still applies. Reset seeds visible scenario contacts to represent an initial completed scan; subsequent scans and track aging use simulation time and freeze when paused. Settings persist across resets.
This is inspired by public descriptions of Eagle pulse-Doppler air-to-air look-up/look-down capability (https://www.af.mil/About-Us/Fact-Sheets/Display/Article/104501/f-15-eagle/). It is not a specific APG-63 variant replica or performance model. Scan width, elevation limits, timing, retention and range scales are fictional game settings. There is no RF propagation, RCS, clutter filtering, Doppler detection, electronic warfare, terrain masking, real IFF or authentic radar/weapon integration. The search view shows scenario contacts above and below the aircraft without ground-clutter simulation.
